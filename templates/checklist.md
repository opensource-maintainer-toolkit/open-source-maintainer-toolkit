# Repository Readiness Checklist

Use this checklist before onboarding your repository to a Drips Wave Program — or any time you want to audit your project’s health.

---

## Essential Files

- [ ] `README.md` — explains what, why, and how
- [ ] `LICENSE` — OSI-approved open-source license
- [ ] `CONTRIBUTING.md` — how to claim issues, set up, and submit PRs
- [ ] `CODE_OF_CONDUCT.md` — Contributor Covenant or equivalent
- [ ] `.gitignore` — excludes OS, editor, and secret files
- [ ] `.github/ISSUE_TEMPLATE/` — bug report, feature request, good first issue
- [ ] `.github/PULL_REQUEST_TEMPLATE.md` — structured PR description

## Repository Settings

- [ ] Description and website URL filled in
- [ ] Topics/tags added (e.g., `open-source`, `maintainer-tools`, `drips-wave`)
- [ ] Default branch is `main` (not `master`)
- [ ] Branch protection enabled on `main` (require PR reviews)
- [ ] Issues enabled
- [ ] Discussions enabled (optional but recommended)
- [ ] Wiki disabled (use `docs/` instead)

## Labels

- [ ] `good first issue` (colour: `#7057ff`)
- [ ] `documentation` (colour: `#0075ca`)
- [ ] `help wanted` (colour: `#008672`)
- [ ] `bug` (colour: `#d73a4a`)
- [ ] `enhancement` (colour: `#a2eeef`)
- [ ] `drips-wave` (colour: `#5319e7`)

## Issues Ready for Drips Wave

- [ ] At least **5 good first issues** created and scoped
- [ ] At least **3 medium issues** created and scoped
- [ ] At least **2 high issues** created and scoped
- [ ] Each issue has:
  - [ ] Clear title starting with a verb
  - [ ] Context and definition of done
  - [ ] Acceptance criteria as checkboxes
  - [ ] Files to modify listed
  - [ ] Complexity assigned (Trivial / Medium / High)

## Community Health

- [ ] Pinned issue welcoming new contributors
- [ ] `docs/contributor-guide.md` exists and is linked from README
- [ ] Response time goal stated (e.g., “We aim to respond within 48 hours”)
- [ ] Maintainer contact method published (issue, Discord, email)

## Drips Wave Onboarding

- [ ] GitHub organisation created
- [ ] Drips Wave GitHub App installed on the organisation
- [ ] Repositories synced in Drips Wave app
- [ ] Repository applied to the correct Wave Program
- [ ] Application approved by Wave Organizer
- [ ] Issues added to Wave with complexity levels set

## Post-Onboarding

- [ ] Leaderboard monitored during active Wave
- [ ] Contributor applications reviewed daily
- [ ] PRs merged promptly to ensure points are awarded before Wave deadline
- [ ] Compliments issued during the 7-day window after Wave ends
