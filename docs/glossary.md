# Glossary of Open Source Terms

A reference for new maintainers. 30 essential terms explained plainly.

| Term | Definition |
|------|------------|
| **Backport** | Applying a fix from a newer branch to an older, maintained release branch. |
| **Breaking Change** | A modification that requires downstream consumers to update their code. |
| **Bot** | An automated account that performs routine tasks (merging, labeling, closing stale issues). |
| **CI/CD** | Continuous Integration / Continuous Delivery — automated testing and deployment pipelines. |
| **Codeowner** | A GitHub user automatically assigned as reviewer for specific file paths via CODEOWNERS file. |
| **Contributing Guide** | A document (CONTRIBUTING.md) explaining how to submit issues, PRs, and code. |
| **Contributor License Agreement (CLA)** | A legal agreement granting the project rights to use contributed code. |
| **Dependabot** | GitHub's automated dependency update bot. |
| **Dependency** | An external library or package the project relies on. |
| **Fork** | A personal copy of a repository where changes can be made before submitting a PR. |
| **Force Push** | Overwriting remote branch history — dangerous, should be used with caution. |
| **Good First Issue** | A label for beginner-friendly tasks with clear scope. |
| **Hacktoberfest** | An annual October event encouraging open source contributions. |
| **Issue Tracker** | The GitHub Issues system for tracking bugs, features, and tasks. |
| **Label** | A colored tag applied to issues and PRs for categorization. |
| **Linter** | A tool that checks code style and common mistakes automatically. |
| **Maintainer** | A person with commit access responsible for reviewing and merging PRs. |
| **Merge Conflict** | When two branches modify the same lines and git cannot auto-merge. |
| **Milestone** | A grouping of issues/PRs targeted for a specific release. |
| **PR Template** | A markdown file (.github/PULL_REQUEST_TEMPLATE.md) pre-filling PR descriptions. |
| **Release** | A tagged version of the software published for users (e.g., v1.0.0). |
| **Semantic Versioning** | A version scheme: MAJOR.MINOR.PATCH (e.g., 2.1.3). |
| **Squash and Merge** | A merge strategy that combines all PR commits into one. |
| **Stale** | An issue or PR with no activity for a configurable period. |
| **Test Coverage** | The percentage of code lines exercised by automated tests. |
| **Upstream** | The original repository a fork was created from. |
| **Version Control** | A system (git) for tracking changes to files over time. |
| **Workflow** | A GitHub Actions automation defined in .github/workflows/. |
| **XSS** | Cross-Site Scripting — a security vulnerability to test for. |
| **Zero-Day** | A vulnerability unknown to the maintainer until reported or exploited. |
